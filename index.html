Current prototype architecture

Anthropic returns a tool-use block to the console harness. The harness relays the tool request to the plugin and sends the result back to the model.

Layer Component Responsibility
Orchestration .NET 10 console executable Reads prompts, keeps in-memory session history, builds the tool catalog, and runs the model/tool loop. Configuration uses ANTHROPIC_API_KEY and optional ANTHROPIC_MODEL.
Model Anthropic Messages API Receives the conversation and tool schemas; returns assistant text or a tool-use request.
IPC Named pipe: AutoCadCopilot.Tools Carries one newline-delimited JSON request and response per connection between the console process and AutoCAD plugin.
AutoCAD integration .NET plugin loaded with NETLOAD Hosts the pipe listener, dispatches requests on AutoCAD's synchronization context, and locks the active document before database operations.

Current code is a terminal prototype, not an ASP.NET Core service. The Electron/React desktop client and localhost WebSocket transport remain in the planned target architecture.

Architecture Diagram

Client and application tier

The desktop client is the user's entry point. In the proposed app tier, the front end uses Next.js, React, TypeScript, and shadcn/ui to present the interface, while the C# backend coordinates application requests and work that needs to be performed.

AI and data tiers

The backend can send suitable requests to an AI provider such as Claude and use the provider's response to select an application action. Supabase and PostgreSQL form the diagram's data tier for persistent application data.

Application Workflow

  1. Enter a prompt. The user describes the drawing request in natural language. In the current prototype, the prompt is entered in the .NET console harness; the desktop interface is still planned.
  2. Select an action. The harness sends the prompt and available tool definitions to the model. The model interprets the request and returns either a text response or a structured tool-use request. Currently, the only drawing tool is create_line (will work on the other tools).
  3. Route the tool call. The C# orchestration layer packages the tool name and arguments as a newline-delimited JSON request and sends it over the AutoCadCopilot.Tools named pipe to the plugin running inside AutoCAD.
  4. Create the geometry. The plugin moves execution onto AutoCAD's synchronization context, locks the active drawing, and dispatches the action. For create_line, it creates a line in Model Space inside a database Transaction and returns the entity handle and endpoints.
  5. Return the response. The tool result travels back to the harness and is sent to the model. The model then produces a natural-language reply for the user. A turn can include up to 10 tool-call rounds; omitted Z coordinates default to 0.

Example pipe request:

Request:
{"tool":"create_line","args":{"start":[0,0],"end":[100,100]}}

Success response:
{"success":true,"result":{"handle":"<handle>","start":[0,0,0],"end":[100,100,0]},"error":null}
