Why .NET plugin over COM automation

Aspect COM automation (previous) .NET plugin (current)
Execution model External process drives AutoCAD over COM Runs in-process, loaded directly inside AutoCAD
Reliability Marshaling/timing issues; needed manual retry delays around every call No marshaling boundary; consistent, predictable behavior
API access Limited automation surface Full native object model (transactions, custom entities, reactors)
Undo / transactions Manual (explicit delete + regen calls) Native Transaction, integrated with AutoCAD's own undo stack
Language interop Python (pywin32), dynamically dispatched C#, strongly typed and checked at compile time
Setup complexity Simple — just attach to a running AutoCAD instance Requires plugin packaging, NETLOAD/autoload, and trusted-path configuration

* .NET plugin wins on reliability, API access, and interop safety — the dimensions that matter most for correctness. COM automation only wins on developer setup simplicity, which is a one-time cost.

Current architecture

Layer Component Responsibility
Client React (Vite, TypeScript, Tailwind) inside Electron Renders the chat UI, sends natural-language drafting requests, and displays tool-execution status and AI responses.
Transport WebSocket (localhost) Streams messages between the Electron renderer and the C# backend, which Electron spawns as a sidecar process.
Backend C# / ASP.NET Core Runs the LLM tool-use loop, maps each tool call to a drawing command, and forwards it to the AutoCAD plugin.
IPC Named pipe Carries serialized tool calls and results between the backend process and the plugin running inside AutoCAD.
AutoCAD integration .NET plugin (in-process) Executes drawing operations directly inside AutoCAD via its native .NET API and database Transactions — chosen because it is AutoCAD's own native automation interface, avoiding the external-process COM marshaling and timing unreliability the previous COM-based prototype had to work around.

* This reflects the newly decided target architecture. The .NET plugin (in-process AutoCAD integration) has been prototyped and validated end-to-end; the C# backend, WebSocket transport, and Electron/React frontend are designed but not yet implemented.
